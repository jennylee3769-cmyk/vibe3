# ELC 영어 MVP 기획서

- 문서 버전: v0.1
- 작성일: 2026-09-07
- 상태: 초안 — 운영 방식 및 가입 정책 결정 필요

## 1. 서비스 개요

### 서비스 한 줄 정의

ELC 영어는 중학생이 학교별 영어 내신 수업과 학습 자료를 찾고, 학생과 학부모가 필요한 수업을 등록·관리할 수 있는 서비스다.

### 주 사용자

- **중학생:** 학년과 학교 진도에 맞는 내신 수업 및 학습 내용을 확인하는 사용자
- **학부모:** 자녀에게 맞는 수업을 살펴보고 등록 현황을 확인하는 사용자
- **운영자:** 수업과 학습 자료를 등록하고 신청 내역을 관리하는 사용자

### MVP가 해결할 문제

1. 학생과 학부모가 어떤 수업을 제공하는지 한눈에 파악하기 어렵다.
2. 학년, 단원, 수업 일정 등 신청에 필요한 정보가 여러 곳에 흩어져 있다.
3. 관심 수업을 확인한 뒤 등록 의사를 전달하고 진행 상태를 확인하는 과정이 불명확하다.

### MVP의 핵심 이용 흐름

`첫 화면 → 수업 목록 → 수업 상세 → 로그인 → 수업 등록 → 마이페이지에서 상태 확인`

> 결제 방식, 실제 수강 확정 절차, 학생과 학부모의 계정 분리 여부는 아직 정해지지 않았으므로 MVP 초안에서는 등록 요청과 상태 확인까지만 다룬다.

## 2. 화면 목록

| 화면 | 목적 | 핵심 구성 요소 | 주요 행동 |
|---|---|---|---|
| 첫 화면 | 서비스의 대상과 가치를 빠르게 전달 | 서비스명, `중등내신수업` 소개, 핵심 장점 3개, 둘러보기 버튼 | 수업 목록으로 이동 |
| 목록 | 개설된 내신 수업을 비교·탐색 | 학년 필터, 과목/영역 필터, 수업 카드, 모집 상태 | 필터 적용, 상세 열기 |
| 상세 | 한 수업의 등록 판단에 필요한 정보 제공 | 수업명, 대상 학년, 설명, 일정, 교재, 정원, 모집 상태 | 등록 화면으로 이동 |
| 등록 | 선택한 수업에 등록 요청 | 신청자 정보, 학생 정보, 학교/학년, 연락 방법, 개인정보 동의 | 입력 확인, 등록 요청 제출 |
| 로그인 | 본인 확인 및 개인 기록 연결 | 이메일 또는 휴대전화, 비밀번호, 로그인 버튼 | 로그인, 가입 안내 확인 |
| 마이페이지 | 개인 정보와 수업 등록 상태 확인 | 사용자 정보, 학생 정보, 등록 수업, 진행 상태 | 등록 상세 확인, 정보 수정 |

### 화면별 최소 요구사항

#### 첫 화면

- 서비스 이름 `ELC 영어`와 한 줄 소개 `중등내신수업`을 표시한다.
- 중학생과 학부모 모두 이해할 수 있는 소개 문구 3개를 표시한다.
- `둘러보기` 버튼을 누르면 수업 목록으로 이동한다.
- 모바일과 데스크톱에서 핵심 문구와 버튼이 잘리지 않아야 한다.

#### 목록

- 수업 카드에 수업명, 학년, 수업 일정, 모집 상태를 표시한다.
- 최소한 학년별로 수업을 좁혀 볼 수 있어야 한다.
- 조건에 맞는 수업이 없을 때 다음 행동을 안내하는 빈 화면을 표시한다.

#### 상세

- 등록 전에 알아야 할 수업 대상, 학습 내용, 일정, 교재, 모집 상태를 표시한다.
- 모집 중인 수업에서만 등록 버튼을 활성화한다.
- 정해지지 않은 정보는 임의로 생성하지 않고 `확정 후 안내`로 표시한다.

#### 등록

- 필수 항목과 선택 항목을 구분한다.
- 제출 전 개인정보 수집·이용 동의를 받는다.
- 등록 후 접수 여부와 이후 절차를 명확히 안내한다.

#### 로그인

- 로그인 실패 시 원인과 해결 방법을 함께 표시한다.
- 로그인하지 않은 사용자가 등록을 시도하면 로그인 화면으로 이동한다.

#### 마이페이지

- 현재 등록 요청의 상태를 `접수`, `확인 중`, `확정`, `취소` 중 하나로 표시한다.
- 사용자는 자신의 정보와 자신에게 연결된 등록 기록만 볼 수 있어야 한다.

## 3. 저장해야 할 데이터

### 사용자 및 학생 정보

| 항목 | 필드명 | 형식 | 필수 | 설명 |
|---|---|---|---|---|
| 사용자 식별자 | `user_id` | UUID 문자열 | 예 | 사용자 고유 ID |
| 사용자 유형 | `role` | 열거형: `student`, `parent`, `admin` | 예 | 학생, 학부모, 운영자 구분 |
| 이름 | `name` | 문자열, 2~30자 | 예 | 사용자 이름 |
| 이메일 | `email` | 이메일 문자열 | 정책 결정 | 로그인 및 안내 수신용 |
| 휴대전화 | `phone` | 문자열, 숫자와 하이픈 | 정책 결정 | 본인 확인 및 연락용 |
| 비밀번호 | `password_hash` | 해시 문자열 | 예 | 원문이 아닌 안전한 해시만 저장 |
| 학생 식별자 | `student_id` | UUID 문자열 | 학생 정보에 필수 | 학생 고유 ID |
| 학생 이름 | `student_name` | 문자열, 2~30자 | 예 | 수강 대상 학생 이름 |
| 학교명 | `school_name` | 문자열, 최대 100자 | 예 | 재학 중학교 이름 |
| 학년 | `grade` | 정수: 1, 2, 3 | 예 | 중학교 학년 |
| 보호자 연결 | `guardian_user_id` | UUID 또는 `null` | 정책 결정 | 학생과 학부모 계정 연결 |
| 생성 일시 | `created_at` | ISO 8601 날짜·시간 | 예 | 최초 생성 시각 |
| 수정 일시 | `updated_at` | ISO 8601 날짜·시간 | 예 | 최근 수정 시각 |

## 4. 이번 과정에서 만들지 않을 기능

- 온라인 카드 결제, 환불, 현금영수증 및 세금계산서 처리
- 실시간 화상 수업 및 녹화 영상 스트리밍
- 숙제 제출, 자동 채점, 성적표 및 학습 분석
- 학생과 강사 간 실시간 채팅 또는 커뮤니티
- 문자, 카카오톡, 이메일 자동 알림 발송
- 학교별 시험지·문제은행 및 AI 문제 자동 생성
- 여러 강사와 지점의 권한을 관리하는 복잡한 관리자 시스템
- 소셜 로그인, 다중 인증 및 외부 학습 플랫폼 연동
- 추천 알고리즘과 개인별 학습 경로 자동 생성
- 앱스토어용 iOS·Android 네이티브 앱

## 5. MVP 완료 기준

- 사용자가 첫 화면에서 서비스 대상과 목적을 이해할 수 있다.
- 목록에서 학년에 맞는 수업을 찾고 상세 정보를 확인할 수 있다.
- 로그인한 학생 또는 학부모가 수업 등록 요청을 제출할 수 있다.
- 마이페이지에서 본인의 등록 상태를 확인할 수 있다.
- 운영자가 수업 정보와 등록 상태를 관리할 수 있다.
- 모바일 390px 이상과 일반 데스크톱 화면에서 가로 스크롤 없이 사용할 수 있다.
- 개인정보와 비밀번호를 안전하게 저장하고 권한에 따라 데이터 접근을 제한한다.

## 6. 결정이 필요한 항목

- 실제 수업이 온라인인지 오프라인인지, 또는 두 방식을 함께 운영하는지
- 학생과 학부모가 별도 계정을 만드는지, 학부모가 학생 정보를 함께 관리하는지
- MVP의 `등록`이 무료 상담 신청인지, 수강 확정 신청인지
